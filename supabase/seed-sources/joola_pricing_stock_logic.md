# 율라 세일즈 컨트롤타워 — 가격/재고 로직 참고 문서

새 사이트에서 견적·재고 기능을 그대로 재현할 수 있도록, 지금 허브(orderHub)가 쓰던 데이터 구조와 계산 로직을 정리했습니다. 같이 보낸 세 개 JSON 파일과 함께 참고하세요.

- `joola_dealers.json` — 딜러 15곳 (KR01~KR16, KR15 결번). 필드: `kr`(딜러 코드), `bizName`(상호), `name`/`recipient`(담당자·존칭 포함), `shipRecipient`(존칭 뺀 배송용 이름), `phone`, `address`, `discount`(할인율 0~1), `paymentTerms`(결제조건), `nextSeq`/`lastSeqYear`(딜러별 견적서 번호 채번용 순번), `specialNote`(있는 딜러만).
- `joola_catalog_prices.json` — 상품 766개 가격표. 필드: `sku`(브랜드 상품번호, 6자리 위주), `name`, `mapPrice`(소비자가/MSRP, KRW), `category`, `type`(`hardgoods` 또는 `apparel` — 아래 가격 공식에서 갈림).
- `joola_current_stock.json` — 2026-09-15 10:20 이지어드민 실사 기준 가용재고 스냅샷. `updatedAt`(실사 기준일시)와 `items[]`(각 `{sku, name, qty}`). 여기서 `sku`는 허브 내부 관리코드(5자리, `joola_catalog_prices.json`의 `sku`와는 다른 번호 체계)이고, `name`은 보통 `"<카탈로그 sku> <상품명>"` 형태로 브랜드 상품번호가 이름 맨 앞에 들어있어 이 값으로 두 데이터를 매칭합니다 (아래 "SKU 매칭" 참고).

## 1. 딜러 단가 계산 공식

소비자가(MAP, `mapPrice`)와 딜러 할인율(`discount`, 0~1)로 부가세 제외 단가를 계산합니다. 카테고리(`type`)에 따라 공식이 다릅니다.

**하드굿즈(패들·가방·네트 등, `type: "hardgoods"`)** — 부가세를 뺀 뒤 할인 적용, 100원 단위 반올림:
```
unitPrice = round( (mapPrice / 1.1) * (1 - discount) / 100 ) * 100
```

**의류(`type: "apparel"`)** — 소비자가에 할인율만 적용(부가세 조정 없음, 원 단위 반올림). 단, 의류는 딜러 등급과 무관하게 전 딜러 60% 고정 할인:
```
unitPrice = round( mapPrice * (1 - 0.60) )
```
(현재 `joola_catalog_prices.json`에는 `type: "apparel"`인 품목이 실제로는 거의 없고, 의류/양말류도 `hardgoods`로 분류된 경우가 많아 그 품목들은 위 하드굿즈 공식이 적용됩니다. 다만 실제 오더리스트를 대조해보면 양말류처럼 하드굿즈 공식보다 낮은 가격이 별도로 책정된 품목이 있어 — 예: 크루삭스는 공식상 약 4,100원인데 실제 딜러가는 3,200원 — 새 사이트에서는 카탈로그 가격표를 100% 신뢰하기보다 오더리스트 원본과 대조하는 절차를 유지하는 걸 권장합니다.)

**배송비**: 별도 품목("배송비")으로, 박스당 고정 5,000원, 할인 없음.

**부가세**: 견적 합계 계산 시 품목 합계(공급가액)의 10%를 별도로 더해 총액을 표시 (품목 단가 자체는 항상 VAT 제외 기준).

## 2. SKU 매칭 (브랜드 상품번호 ↔ 내부 재고코드)

두 데이터셋의 연결고리는 "이름 맨 앞에 붙은 브랜드 상품번호"입니다. `joola_current_stock.json`의 각 품목 `name`은 다음 규칙으로 만들어집니다.

1. 이름 앞에 `"율라코리아"` 접두어가 붙어있으면 제거.
2. 그 다음 맨 앞의 숫자열(3자리 이상 연속 숫자)을 브랜드 상품번호로 추출 — 이 번호가 `joola_catalog_prices.json`의 `sku`와 같은 값입니다.
3. 나머지 문자열이 실제 상품명.

의사코드:
```js
function extractLeadingCode(name) {
  const n = name.replace(/^율라코리아/, "").trim();
  let m = n.match(/^(\d{3,})[,]?\s+(.*)$/) || n.match(/^(\d{3,})(\S.*)$/);
  return m ? { brandSku: m[1], productName: m[2].trim() } : { brandSku: null, productName: n };
}
```
새 사이트에서 재고와 가격표를 하나의 상품 테이블로 합치려면, 이 규칙으로 `joola_current_stock.json`의 `name`에서 `brandSku`를 뽑아 `joola_catalog_prices.json`의 `sku`와 매칭하면 됩니다. (매칭 안 되는 품목도 소수 있을 수 있음 — 신상품이라 아직 가격표에 없거나, 반대로 가격표엔 있지만 현재 재고가 0이라 이번 실사에 안 잡힌 경우 등.)

## 3. 재고 최신화(실사 반영) 워크플로

지금 허브는 이지어드민에서 내려받은 "현재고조회" 엑셀(HTML 포맷의 .xls)을 주기적으로 전달받아 아래처럼 처리해왔습니다.

1. 엑셀에서 `상품코드`(브랜드 번호), `상품명`, `가용재고`(정상재고 − 출고요청대기수량) 열을 읽음. `가용재고`가 실제 판매 가능 재고 기준값 — `정상재고`가 아니라 이 값을 씀.
2. 브랜드 상품번호로 기존 재고 목록과 매칭해서 `qty`를 새 값으로 갱신.
3. 실사 기준일시(`updatedAt`)를 엑셀 파일명에 있는 타임스탬프로 갱신.
4. 이전 실사 이후 신규 견적서에서 출고된 수량은 "자동 차감"으로 별도 누적해뒀다가, 새 실사 반영 시점에 그 누적치를 초기화(이중 차감 방지) — 즉 "실사 재고" = 정기 스냅샷, "자동 차감" = 그 사이 견적서 저장분을 임시로 반영한 보정치, 두 개를 구분해서 관리하는 구조입니다.

새 사이트에서 재현할 때 핵심은: **재고의 진실 소스는 사람이 주기적으로 올려주는 실사 엑셀이고, 그 사이의 판매(견적서 저장)는 임시 보정치로만 반영한다**는 이원 구조입니다. 실시간 재고 연동(이지어드민 API)은 공식 API가 없어 불가능해서 이 방식으로 운영 중입니다.
